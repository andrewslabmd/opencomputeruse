# Architecture

The native menu-bar process holds an OS file lock and launches one helper and one host service. Every observation, capture and action is OpenComputerUse's own code in that helper and the engines; no third-party automation backend is bundled or launched. MCP/CLI connect to the host over a private Unix socket; the host supervises one lazy private broker (engine) per client workflow, plus a read-only broker that never starts an engine.

The host authenticates local clients with an installation token in its owner-only runtime directory. This is a same-user local trust boundary, not isolation from malicious processes already running as that user. Client names are untrusted labels. Disconnect (revoke) closes a connection and tells that client not to reconnect by itself; the agent's next connection is accepted, since persistent per-client credential revocation remains future work.

Host restarts are transparent to clients. A CLI or MCP request on a closed connection reconnects (waiting up to 10 s for a restarting host, launching the app when needed) and registers again. A request in flight when the connection closes fails once with `host_disconnected`; read-only requests (status, tool listing, permissions) are sent once more to the new host, observations and actions never are. The new host has no workflow, so acting requires a fresh observation.

The host exits when its app exits (parent gone or reparented). It stops listening and removes its socket before native cleanup, and removes the path only while it is still its own socket. A host starting while another answers on the socket asks it for its PID and app PID: one whose app has exited, or that is closing, is stopped (TERM, then KILL); one whose app is alive stays and startup fails with `already_running` naming both; one that does not identify itself gets 5 s to exit by itself. The app restarts a host that exits by itself with backoff (immediately, then 2, 4, 8, 16 s) and after five starts within a minute shows the host's last error and asks for Restart Services.

Agents work concurrently, one per application. Each client's workflow has its own engine process (observation, element ids, delivered snapshot, action queue) and claims at most one application process. Before an observation, or a batch containing open_app, the host resolves the target to its running process (helper `resolveApplication`, read-only) and refuses `busy` when another client holds that process, before anything is collected or sent. The claim follows the process each result reports: observing another app moves it, a failed observation ends it, and a target that was not running is claimed from its new process (busy, with the observation reset, if another client claimed it meanwhile). Each client runs one call at a time; different clients' calls run in parallel. An action batch needs the client's own observation. Release resets only that client's engine; disconnect stops it; idle expiry (120 seconds without a call in flight) applies per workflow. A client's cancel (MCP cancellation) stops only its own workflow. The app's Stop pauses the host and stops every workflow, rejecting pending work. Already-dispatched native actions may finish; cancellation is not rollback. A fresh observation is required after ownership loss. Status lists `workflows` {client, app_pid, busy}; `owner` is the most recently active claiming client, which the menu-bar preview follows.

The helper keeps each agent's latest observation (native handles, windows, keyboard scope, process identity) separately, keyed by the requesting engine's process identity. Native requests still run one at a time on the helper's native queue, and each loads its own agent's observation, so one agent's request never validates against another's handles; a long observation delays other agents' native requests until it finishes. A parked observation is dropped once its engine's process identity no longer matches. Background focus holds one lease per agent: each agent's app keeps its own synthetic activation, and a lease for a process another agent's lease targets is refused. Releasing one agent restores only its app. Input observers stop only when no lease remains.

The native helper owns a background app-focus lease tied to the broker PID and target kernel process-start identity. Activation is on demand because it raises the target's window in the window stack (never the foreground app): keyboard input, Return-submit and explicit pointer input (clicks, pointer drags, long presses) activate before dispatch. For other actions the native executor reports `app_activation_required` before dispatching anything when it needs activation (window-bound pointer input, popup/menu buttons, context menus); the engine then activates and repeats that same undispatched request once. Plain Accessibility operations do not activate. Before an action that needs it on a logically inactive app, it sends a PID-directed AppKit activation notification (event type 13, subtype 1), without changing Window Server's foreground app. The lease persists across actions and observations in that workflow so menus remain usable. A PID-specific event tap watches only app-state notifications, preserving the owned activation until release and yielding to real user activation. It never intercepts physical mouse or keyboard events. Recoverable action and observation errors do not end the owned workflow or deactivate an app whose UI may already have changed. Normal release, target changes, Stop and disconnect unwind the lease; a native process-exit watcher also restores it if the broker dies, independently of main-thread snapshot collection. Restoration uses subtype 2 only for the same process and state owned by the helper. Existing logical activation and user activation are preserved. Unconfirmed restoration blocks subsequent activation rather than repeating an uncertain notification. Native state acknowledgement has a bounded wait; this adds no task-duration limit. Helper crash recovery remains unverified.

Process identity comes from public `proc_pidinfo(PROC_PIDTBSDINFO)`: PID, UID and integer start seconds/microseconds. Missing optional LaunchServices launch dates do not imply exit. Snapshot publication, action/focus/keyboard preflight, each native receiver and lease cleanup check the same identity. Lookup failures remain errors; they are not treated as confirmed exit or permission to discard ownership.

Application surfaces retain meaningful AX window-list roots, including standalone editable controls. The native AX window-number bridge associates them with Window Server IDs; only ordinary AXWindow roots with unavailable IDs may use unique exact-frame matching. Keyboard scope can include a focused editor overlay only when the app's main window is the pinned document. Explicit window_id/title scope excludes unrelated intersecting windows; title scope must resolve uniquely. Related overlays require native window/ancestor ownership or a verified focused editor tied to that main window. Scoped screenshots retain the same proven window set. AX/Window Server inventory and mapping failures have separate stage errors.

Sheets, menus and popovers can extend beyond their owning window's frame. AX ancestry expresses ownership, not clipping. Only scroll viewports clip descendants; nested scroll viewports intersect, while independent sheet/menu/window UI resets inherited clipping. Retained descendant geometry can select that window's scope when its root geometry agrees with the window. The helper then verifies live AX window ancestry, geometry and receiver identity. A blank gap or conflicting snapshot geometry does not authorize an overflow action.

Host transport: version 1 JSON lines, request IDs, 8 MiB inbound limit, private socket mode 0600 and directory mode 0700, local bearer token, bounded request deadlines. Tool arguments are validated against the same schema served over MCP. Engine tools are observation, action batch and permissions; the host answers application listing itself; release/status are adapter lifecycle tools.

The initial engine remains JavaScript. Incremental TypeScript migration, stronger per-client credentials, and richer activity presentation are not complete. Helper file IPC is retained internally. Public distribution needs complete dependency notices and release validation.

Permission preflight goes directly to the helper and does not start the action broker. The broker checks the current permission fingerprint before action dispatch; a change restarts capability negotiation and requires a new observation before a queued action can proceed. Abort signals are checked after asynchronous preflight and initialization. The host exits if its native parent dies.

Observations return the full collected hierarchy as compact flow YAML. The agent encoding drops only redundancy: bare native ids (resolved against the observation that returned them; prefixed references remain accepted), `offscreen` stated once on a subtree root, `selected` only when true, unfocused empty selection ranges omitted, and frames inherited from the parent when equal (`frame: null` = none). A subtree that is offscreen throughout, and therefore not actionable, is sent as one line with its id, role, selected/focused flags and every distinct text it contains; its inner cell structure is the only information not sent, and `scroll_to_visible` on its id returns it in full. Internal trees, targeting and observed_changes keep every node and field. Action-batch results are sent as changes against the model the agent last received (an observation or previous batch result) for the same process: identical windows/subtrees become `unchanged: true` stubs with the same stable native id; anything new or changed is complete; observation failures, resets and process changes send the full model. When an app rebuilds its tree (Notion opening a side panel re-created about 780 elements), the result is effectively full; local changes shrink about 15× (Notion panel close: 88 KB → 5.8 KB). Measured on 2026-10-15 trial results: Finder 2.05 MB → 280 KB, Notion 111 KB → 65 KB, with no text lost. The engine imposes no text-size cutoff or paging; clients manage results that remain large through their saved-result mechanisms; the Claude integration must retain the normal built-in tools needed to retrieve persisted results.

Native traversal reads each node's 17 presentation/state attributes, including UTF-16 selection range, native AXURL and AXDocument, in one AXUIElementCopyMultipleAttributeValues request. Unsupported/missing attributes remain local to that field. Stale-element, messaging and permission failures abort the capture; they cannot masquerade as missing children. An invalid UI element restarts the complete capture from fresh roots under the same kernel process identity, with cancellation checks and no action replay. Other failures invalidate the capture. Successful restarted captures expose collection_restarts. Providers reporting the batch API as not implemented use individual reads for compatibility. Action names and writable attributes are not enumerated during snapshot collection. Standard operations are inferred from role and attempted on the validated target; custom controls and unsupported attempts query only the relevant target/ancestor path. Native commands run on a serial worker; permission reads/prompts and focus release remain on the main command loop. Collection checks the request file and exact owner kernel identity between provider operations. Caller cancellation/removal or owner death stops traversal, discards partial handles and prevents publication; individual AX calls have the existing bounded messaging wait. The collector inventories all window roots before iterative traversal, compares actual AX handle equality (not only hashes), and visits the deduplicated union of AXChildren and AXContents without node/child/depth ceilings. Unnamed native groups retain their identities because they can own real operations, without enumerating their action lists. Provider failures are observation errors, not partial successful trees.

Each published node id contains an opaque observation generation and retained native identity. Exact `element` targets bypass topmost-window point lookup, bind to the same native handle/window and validate its live identity, role, ancestry and geometry. Native IDs carry forward only on actual CFEqual handle equality in the same kernel process; CFHash is only a bucket key. Batch references bind once and can survive internal captures only while that exact handle remains in the same window. They expire for later tool calls. Unrelated, stale, moved or offscreen targets fail before dispatch; scroll_to_visible is the explicit exception for an exact offscreen handle, invoking only its advertised AXScrollToVisible operation without pressing or focusing it. open invokes advertised AXOpen on the exact target path. Neither changes click-selection semantics. `select_text` verifies one exact unique substring, UTF-16 range and resulting text without key presses.

For spatial actions, one helper request validates the observation generation and kernel process-start identity, pins the current app window, performs app-scoped macOS Accessibility hit-testing and refines coarse hits inside their retained subtree by frame containment. Unrelated equally precise or crossing hits fail as ambiguous. Every execution/fallback uses only that validated target/ancestor chain, checks live identity, ancestry, geometry, and acts on the exact retained AX handle. Enabled state gates the actual interactive receiver and genuine disabled controls, not every read-only page/section/layout ancestor. Native layout identities are retained even when unnamed or unselected; role and naming alone cannot establish that a group is inert. JavaScript validates coordinate space and forwards the native result; it neither chooses an interaction nor asks the backend to resolve the point again.

Click selection is planned separately from geometric hit resolution. Readable AXSelected is state, not evidence of item membership. A writable AXSelectedRows receiver requires the targeted row in its live AXRows; AXSelectedChildren requires a live AXChildren item on the validated target path. Standard AXCollectionList / AXSectionList relationships expose section items to the enclosing collection's selection setter; arbitrary layout ancestors are not flattened. The selected item may contain the image or label at the point. Membership is rechecked immediately before mutation and the resulting selection must contain exactly that single item. Ambiguity, changed membership and accepted-but-ignored setters remain failures; no speculative second mutation is attempted. Press controls and genuinely editable fields retain their own click behavior. Text-field role alone does not establish caret support: a writable AXSelectedTextRange is required, so readonly labels inside rows select the row instead. Selection relationship/capability reads occur only on the action path, without enlarging snapshots or adding model tool calls.

Native results identify each actual operation and receiver. Left clicks never substitute AXShowMenu. Selection is reported as selection, not navigation. Unsupported operations return target-scoped supported information in the same response. Other native errors stop without trying another target, since an uncertain failure may already have changed state. Menu/action calls still running after their short return grace are reported pending, stopping the batch; they are not labelled completed. Repeating the same still-pending native handle/action does not dispatch another call. Accepted calls do not establish the user's semantic outcome. Post-action observations remain the source for task verification. Text insertion preserves Unicode selection semantics; Submit uses advertised native AXConfirm on the retained field when available, without taking focus. Otherwise Return uses the helper’s audited PID-directed keyboard dispatcher only after the exact edited field is confirmed as the app’s focused element. AXConfirm failures do not fall through to Return. Literal text, Return and standalone hotkeys share that dispatcher. Text clicks map the requested native point to a collapsed insertion range and read it back. Text/value/selection setters confirm their observable state. After an accepted text mutation, the exact retained editor is checked again for process, role, window and ancestry, then its live frame is refreshed before cursor/focus follow-ups. Those follow-ups validate the refreshed receiver instead of requiring the original click point to remain inside a control resized by our own write. Pre-write geometry checks still reject unexpected movement. Already focused fields avoid a redundant AXFocused setter; Return still requires the exact app-focused receiver. Scroll first uses the explicitly associated retained scrollbar, validating its window, live ownership link and geometry; the bar need not contain the owner point. Native scrollers linked to an AXScrollArea use their relative-position contract when bounds are absent or degenerate 0/0 and the current value is finite within 0..1; arbitrary scrollbar-role controls and sliders require usable explicit bounds. Valid explicit custom ranges take precedence. The same ownership check applies to direct native scrollbar adjustment. Page extent comes from content/knob geometry. Missing range/extent does not suppress native page actions. Numeric writes carry private expected-state metadata; direction/value is confirmed from the existing fresh post-action snapshot rather than assuming a remote provider updates its AX cache synchronously. An accepted but unconfirmed state change stops dependent batch steps as unconfirmed, without claiming rejection, replaying it, or adding a wait. Unexpected action errors (including attributeUnsupported from PerformAction) stop rather than dispatching alternatives. Native return codes are recorded as errors, not assumptions of rejection.

These validations reduce stale-target risk without making an asynchronously changing application atomic. Stop is not rollback of an already-dispatched native call. Provider reads and encoding still have real failure modes, and live app changes are not atomic. Collection publishes a complete traversed scope or an observation error; it does not silently return a count-truncated tree. Native provider virtualization or unsupported AX fields remain unknown.

Electron web content accepts AXPress but drops it until Chromium's complete accessibility mode is applied. On the first observation of a process whose application element advertises a settable `AXManualAccessibility`, the helper requests it once per kernel process identity and waits out Electron's own two-second debounce (cancellable) before collecting. Electron's getter cannot confirm the switch, and Electron keeps one shared mode, so the request is not reverted on release: a disable could remove a mode another assistive client requested. Retained AX handles survive the switch. Targets without the switch are not changed, and AXEnhancedUserInterface is never set. A completed AXPress inside an AXWebArea is confirmed against the fresh post-action capture: an identical receiver window (ignoring native handle ids) reports `unconfirmed` / `press_effect_unobserved` and stops dependent steps, without replay. Native AppKit presses keep their existing semantics.

Pointer clicks are window-bound, process-directed input. `click` with `input_method: "pointer"`, a web-content hit with no native operation, or a generic web AXPress (canvas, click-handler regions, where Chromium's simulated press lands at the element origin) builds left-button events with the public NSEvent constructor carrying the retained window number. The location is window-local, as the receiving AppKit reads it. A private event source is used and events are posted only through `postToPid` via the audited input dispatcher (tags, listen-only receipts, identity recheck before the down event, guaranteed up event). The physical cursor does not move and the foreground app does not change. The receiver accepts such events only while logically active, so dispatch requires AXFrontmost and otherwise fails before input. Never dispatched after another operation was attempted. The same path carries pointer gestures: `long_press` holds the button at a point for `duration_ms` (default 800), and `drag` with `input_method: "pointer"` (or a web-content drag without an adjustable control) presses at `from`, sends left-dragged moves about every 16 ms to `to` over `duration_ms` (default 300, at most 5000) and releases; both points must lie inside the retained window. Timed events are restamped as they are posted, so receivers measuring holds or swipe velocity see real timing. Between timed events the receiver and cancellation are checked again; if anything fails mid-gesture the button is released where the pointer last was, never at the unreached end. Pointer and web-press receipts are confirmed against the receiver window using the same definition as observed_changes; no observed change is `unconfirmed`. observed_changes also reports named elements added or removed, so panels built from plain groups are visible. `click_count` 2–3 and `modifiers` always take this path, since Accessibility has no repeated or modified press: each press carries its position in the series as the NSEvent click count (down/up 1, down/up 2, …), posted back to back, and modifiers are flags on the mouse events themselves (NSEvent modifierFlags and CGEvent flags). No flagsChanged event or physical modifier press is sent, so a receiver that reads the global modifier state instead of the event's would not see them. Synthetic activation (subtype 1) raises the target's key window to just below the frontmost app's window, and deactivation does not restore z-order (measured on Electron 43.6.0). This is why activation is on demand; a non-raising activation remains unresolved.

Context menus opened with AXShowMenu are separate Window Server windows whose AX parent chain does not reach the owning window, though the snapshot finds them under the window's tree (Finder lists the menu as a child of the sidebar outline). A menu item belongs to the observed window only when its nearest AXMenu is the exact retained menu (native handle equality) present in that window's observed tree; stale or unrelated menus are rejected. The same retained menu relates the observed containers above it (the opener and its window) when a menu's own parent chain does not reach its opener, so operations on the menu itself (perform_action AXCancel) validate the whole observed path. Verified live: Finder sidebar right-click → Open in New Window, both directly from the right-click result and after a scoped or whole-app observation. Any click elsewhere on screen closes an open context menu, so menus are fragile while the user clicks. Selection whose immediate readback does not show the item is confirmed from the fresh capture: item selected (selection_set), its window changed (selection_changed_window, e.g. Finder navigating) or unconfirmed; selecting extra items remains a failure. A hotkey refused because OCU's own fresh activation moved the app's focus (nothing sent) is observed again and repeated once; a focus change after an existing activation is never retried. The foreground guard also covers lease cleanup requests.

Foreground guard: the user may bring any app forward at any time, including the one an agent is working in. The guard only undoes an app taking the front as a reaction to OCU's own input. It arms only when OCU posts keystrokes or pointer clicks (the audited dispatcher) and around app launches, because macOS only lets an app activate itself after real input delivered to it; it never arms around Accessibility actions, activation, cleanup or observation. It watches for 1.0 s, at most one correction per input. Any physical click (from 0.5 s before the input) or Command/Control held during the window (Cmd+Tab, Spotlight, Spaces) counts as the user's choice and the guard stands down. Otherwise it re-fronts the previous app via AXFrontmost (activation fallback) and reports `foreground_guard`. Only input timing and modifier state are read, never key content. Working inside the already-frontmost app never triggers it. A first version armed around every request for 1.5 s and ignored Cmd+Tab toward the target; it repeatedly pulled the user back while they tried to watch an agent work, and was replaced.

Application-window capture neither activates the target nor generates pointer or keyboard input. Concurrent human cursor movement or switching apps does not invalidate a screenshot. Optional capture errors are reported alongside the valid Accessibility observation so the agent can continue from it.

Named-window observations pin the resolved window ID across post-action capture, including title changes and overlapping app panels. Keyboard preflight requires app-internal focus in that scope; explicit focus changes inside the target app are allowed whether or not it is frontmost. Editor clicks verify the application's AXFocusedUIElement, not merely a control's window-local AXFocused flag. A background editor's retained owning window is selected through writable AXMain when available, with AXFocusedWindow identity checked before proceeding; sheets/menus do not select their parent document out from under modal UI. Native control focus remains usable when AXMain is unavailable, and its actual receiver must still match. Scoped closure is confirmed against Window Server and returned as an empty, non-actionable scoped observation. Each attempted action gets one post-action capture; no duplicate final traversal is made. Results describe measured state changes without generic task-outcome boilerplate. A key event reports sent, with its checked receiver and resulting state; ignored shortcuts are not claimed to have achieved formatting or navigation. Bounded selected text-style runs are queried only for editable selections (4096 UTF-16 units/32 runs maximum); native underline/strikethrough flags accompany font traits, and absent data is unknown. Screenshots remain available for appearance/layout verification. Snapshots keep numeric/boolean values and exact editable text. Compact YAML and normal client saved-result reading remain unchanged.

Apps can hide/cache a closed panel or animate it while AX and Window Server disagree. When the pinned window has no observable surface, return an empty, non-actionable observation with `unavailable_window_id`; this describes unavailable observation, not absence or destruction. Use `closed_window_id` only when a successful Window Server inventory confirms the ID is gone. Both invalidate retained handles and preserve the pinned scope; neither implies that other overlapping windows disappeared. No delay or extra AXWindows read is required to infer a lifecycle transition.

A successful empty AX window inventory can precede Window Server dropping cached surfaces. After normal root/fallback resolution, an empty application scope is a valid non-actionable observation, including an unscoped observation after the last window closes; it does not claim process exit or destruction of cached windows. An exact pinned window absent from a successful inventory of known native window IDs is likewise unavailable. Unknown window identities and failed inventories cannot establish these states. State diffs describe unavailable windows as not observable, preserving the distinction from confirmed absence.

Post-action collection validates the exact prior observation generation and process-start identity. A definite kernel process exit produces a terminal, empty, non-actionable observation, independently of action kind or app. Process replacement and identity lookup failure remain observation errors and cannot authorize interaction with a replacement PID. Both helper and engine invalidate failed observation handles. Native dispatch receipts are preserved when subsequent collection/diffing or focus cleanup fails; observation/execution errors are separate fields and stop the batch without replay. Failed or pending native operations remain failed/pending even if exit is observed. An accepted final operation plus confirmed exit can complete the batch; further queued actions are not dispatched to a departed target.

`perform_action` invokes one Accessibility action by name on the exact resolved target only (chain[0]), never on a container, and only when that element currently advertises it; otherwise nothing is sent and the target path's advertised actions are returned as `supported`. Without a name it sends nothing and returns them (behavior `list_actions`). AXShowMenu, and AXPress on a menu opener, require activation like right_click. AXPress keeps the `press` behavior, so web presses are confirmed as above. Capabilities are still read at the point of use, never while collecting a tree.

Application listing (`use_list_apps`) is answered by the helper on its control path from NSWorkspace and the Window Server window list: regular apps plus any app showing an on-screen layer-0 window, with layer-0 windows that are on screen or titled. LaunchServices entries without a recoverable pid are left out. It never activates, observes or launches, does not take or disturb workflow ownership and is allowed while another client owns the host, but it is refused while paused, since window titles are app content.

Agent cursor overlay: before each spatial action an engine sends the host an `engine/cursor` notification with the target process, window and global point (and a drag's end point). The host keeps the latest cursor per workflow, labels it with the client's name (an MCP adapter uses the agent's own MCP client name) and a stable color slot, and writes the list atomically to the private `cursors.json`, listing only workflows that still hold the cursor's process; release, cancel, Stop and disconnect withdraw it, and host shutdown writes an empty list. The menu-bar app polls the file and the on-screen window list every 50 ms and keeps one borderless, non-activating, click-through panel per agent at normal window level, sized to the target window and ordered directly above it (re-stacked when the target is raised, for example by OCU's own activation; hidden when the window is minimized, hidden or on another Space). Windows in front of the target therefore also cover the cursor. The panel never becomes key or main and ignores mouse events, so it receives no input; process- and window-bound input and app-scoped Accessibility hit-testing are unaffected, and OCU's captures include only the target's windows. Verified live with `scripts/test-native-overlay.mjs`.

Read-only permission inspection bypasses action ownership/busy/paused gates and never replaces the in-flight abort controller. It reads the helper directly without resetting the broker or changing the permission fingerprint. The next action/observation preflight still detects changed grants and invalidates old action state.


Input isolation binds operations to retained native process/window/control identities, independent of foreground status. Direct Accessibility edits can target an authorized foreground document or a background control. Focus-changing setters may move focus to the retained control inside the target app, including the frontmost app the user asked the agent to work in. What is never done is bringing a non-frontmost app to the front, global input, or moving the physical cursor. Keyboard text verifies the retained editor; standalone shortcuts retain the actual focused window/control across observation collection and reject any change before dispatch, including a different control inside the same observed window. Submit binds the exact edited control explicitly rather than adopting whichever control is now focused. Unknown or unstable keyboard scope rejects that operation, without invalidating otherwise usable native AX controls.

Surfaces that take keys but expose no editor (canvases, remote and device screens such as Device Hub's iPhone view, games) get `type` as keystrokes. When the point has no editable control and is not on a control (button, slider, row, tab), the keyboard method sends each character as one key press at its US-ANSI key position, with its text attached and Shift pressed and released through the private source, paced 12 ms apart, to the app process only. The target window must be the app's keyboard window (selected through AXMain like an editor's window), and the app's AXFocusedUIElement must be the surface at the point, one of its containers, or nothing; it is checked again before every key press. Focus on any other control refuses with `keyboard_focus_elsewhere` before anything is sent, so keys never reach a control the agent did not point at; a pointer click on the surface usually gives it focus. Characters without a key position (accents, emoji) refuse the whole text before dispatch, because such receivers read key codes rather than the text payload. `replace` is refused; `submit` appends Return. Every held key or modifier is released if dispatch stops midway. Results are `sent`, then `unconfirmed` (`keyboard_effect_unobserved`) when the fresh tree shows no change in that window; pixels-only surfaces need a screenshot. The direct Accessibility input method still requires an editor (`target_not_editable`).

The dispatcher rechecks cancellation, process identity and receiver immediately before key-down. It uses an independent private Quartz event source, explicit modifier flags on the primary key, no physical modifier presses, no clipboard and only public postToPid; there is no global input fallback. Human app switching does not cancel a correctly bound operation.

Before dispatch, listen-only PID-specific keyboard taps must be available for the target and the current foreground app. They ignore events whose source tag was not created by this dispatcher, without reading keys, Unicode or flags. Known tags produce metadata receipts identifying the intended process/window/editor, watched processes, actual observed process delivery, posted/received counts and foreground before/after. Receipts are attached after the existing post-action capture; wrong-process delivery stops keyboard dispatch, and unavailable/unobserved delivery stops dependent batch steps. Foreground changes update watched-process coverage before key-down; a later coverage change is diagnostic metadata rather than an automatic foreground ban. A private mode-0600 input-audit.jsonl records preparation before dispatch and later observations, never plaintext or human input. Process-stream receipt does not prove a semantic app effect, every possible recipient, or absence of indirect app side effects. The failure latch is process-local; Pause is persisted separately.

Pause is stored atomically in private control-state.json and survives host/app replacement. Initial migration retains the previous status.json paused flag; malformed control state remains paused. Only explicit Resume clears it. Permission inspection remains available while paused. The inputAuditStatus helper diagnostic installs and removes passive taps without posting input, activating apps or prompting for a grant. Live keyboard acceptance remains separate from headless contracts and passive availability.
